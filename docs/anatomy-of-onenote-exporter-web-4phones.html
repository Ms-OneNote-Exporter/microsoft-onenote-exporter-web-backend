    topology, not an allowlist: runners share the msout-runner net but each holds only its own vault/<guid> and artifacts/<id> mounts. denies are routing properties asserted from live containers; internet egress stays open by decision.

    01socket monopoly

    Only the orchestrator mounts /var/run/docker.sock. Verbs are allowlisted — claim · release · recycle · remove · stat — and no request field ever reaches a docker argv.

    02credential physics

    No JSON parser exists on /api/credential. Bytes stream browser → caddy → api → runner via undici, unparsed. Body logging off everywhere, asserted by buffer equality over a real socket.

    03one user, one cage

    A session binds lazily to exactly one runner slot at credential time; an abandoned session never holds a slot. Slots are recycled, never reused warm — six users means six containers, six netns, six mount sets.

    04opaque artifacts

    Downloads are /files/<artifactId> with artifactId = base64url(randomBytes(32)). No GUID, no notebook name in any URL; partials self-label .partial.zip, server-enforced.

    05busy ≠ stuck

    No idle slot and a pool that cannot fill are different answers: the 503 carries cause: "pool-unfillable" with the orchestrator's fillError, so a client told "busy" has something to escalate with.
